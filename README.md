# Family Tree Genealogy System

This repository is designed to help you version, share, and preserve your family tree for future generations.

## Repository Choices & Privacy

Consider the privacy implications of your data. For highly sensitive information, you might opt for private repositories or encrypt specific files.

## Recommended File Formats & Folder Layout

This repository follows a recommended structure for organizing your family tree data and related assets.

```
family-tree/
├─ README.md
├─ family.ged            # GEDCOM export (standard for genealogy)
├─ family.json           # structured JSON with meta & notes
├─ docs/
│  ├─ family.mmd         # Mermaid or Graphviz source for diagram
│  ├─ family.svg         # generated diagram (committed or generated by CI)
│  └─ photos/            # small thumbs (real photos tracked with LFS)
├─ archive/              # PDFs, scanned certificates (encrypted or LFS)
├─ .gitattributes
├─ .gitignore
└─ .github/
   └─ workflows/
      └─ build-diagram.yml
```

## Handling Photos & Big Files (Git LFS)

For large files like high-resolution photos or scanned documents, use Git Large File Storage (LFS).

1.  **Install Git LFS:**
    ```bash
    git lfs install
    ```
2.  **Track file types:**
    ```bash
    git lfs track "*.jpg"
    git lfs track "*.jpeg"
    git lfs track "*.png"
    git lfs track "*.pdf"
    # Add other large file types as needed
    ```
    These commands will add entries to your `.gitattributes` file.
3.  **Add and commit files:**
    ```bash
    git add .gitattributes
    git add docs/photos/my_photo.jpg
    git commit -m "Add photo with Git LFS"
    git push
    ```

## Encrypting Sensitive Docs

For highly sensitive documents, consider encrypting them before committing. Tools like GPG or `git-secret` can be used.

## Lightweight Automation (GitHub Actions) to Build Visuals

You can use GitHub Actions to automatically generate visuals (like `family.svg` from `family.mmd`) whenever changes are pushed.

An example workflow (`.github/workflows/build-diagram.yml`):

```yaml
name: Build Family Diagram

on:
  push:
    branches:
      - main
  workflow_dispatch:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install Mermaid CLI
        run: npm install -g @mermaid-js/mermaid-cli
      - name: Build Diagram
        run: mmcd -i docs/family.mmd -o docs/family.svg
      - name: Commit and Push
        run: |
          git config user.name github-actions
          git config user.email github-actions@github.com
          git add docs/family.svg
          git commit -m "Update family diagram [skip ci]" || echo "No changes to commit"
          git push
```

## Backup & Handing-Off Tips

-   Regularly push your changes to GitHub.
-   Ensure your `family.ged` and `family.json` files are always up-to-date.
-   Document any specific tools or processes you use in this `README.md` or a separate `CONTRIBUTING.md`.
-   For handing off, ensure the recipient has access to the repository and understands the structure and tools used.
